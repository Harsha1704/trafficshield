## 1. The Three Feature Ordering Contexts

To avoid any ambiguity, the TrafficShield inference pipeline defines features across three distinct ordering contexts:

1. **Context 1: Input Ingestion Contract (`feature_names_in_`)**  
   The ordered list of columns expected by `preprocessor.fit()` and audited by `ProductionInferenceService`:
   - 10 Base Features (`REQUIRED_BASE_FEATURES`): `duration_seconds`, `fwd_bytes`, `sttl`, `sload`, `fwd_packets`, `swin`, `smeansz`, `sjit`, `sintpkt`, `is_sm_ips_ports`.
   - 3 Causal Derived Rates: `packet_rate`, `byte_rate`, `bytes_per_packet`.
   - Position of `is_sm_ips_ports`: **Index 9**.

2. **Context 2: Transformer Output Contract (`feature_names_out_`)**  
   The column order generated by `preprocessor.transform()` / `preprocessor.transform_df()`:
   - Block 1 (Numeric Features, 12 columns): `duration_seconds`, `fwd_bytes`, `sttl`, `sload`, `fwd_packets`, `swin`, `smeansz`, `sjit`, `sintpkt`, `packet_rate`, `byte_rate`, `bytes_per_packet`.
   - Block 2 (Boolean Features, 1 column): `is_sm_ips_ports`.
   - Position of `is_sm_ips_ports`: **Index 12**.

3. **Context 3: Estimator Input Contract (`booster.feature_names`)**  
   The internal feature names registered inside the frozen XGBoost tree ensemble:
   - Total features: **13**.
   - Names: `['duration_seconds', 'fwd_bytes', 'sttl', 'sload', 'fwd_packets', 'swin', 'smeansz', 'sjit', 'sintpkt', 'packet_rate', 'byte_rate', 'bytes_per_packet', 'is_sm_ips_ports']`.
   - Position of `is_sm_ips_ports`: **Index 12**.

## 3. Why the Preprocessor and Detector Are Guaranteed in Sync

1. **Training Pipeline Provenance:**
   In Milestone 8, the XGBoost estimator was trained using:
   ```python
   self.preprocessor.fit(train_features)
   X_train = self.preprocessor.transform_df(train_features)
   model.fit(X_train, y_train)
   ```
   Because `X_train` was generated by `transform_df()`, the DataFrame passed to XGBoost had columns strictly ordered by `feature_names_out_`.
2. XGBoost automatically recorded `X_train.columns` as its internal `booster.feature_names`.
3. In production scoring (`ProductionInferenceService.predict_single`):
   ```python
   df_flow = self.validate_and_prepare_input(flow_data)
   x_input = self.preprocessor.transform_df(df_flow)
   score = float(self.model.predict_proba(x_input)[:, 1][0])
   ```
   `x_input` is guaranteed to have the exact column names and column order as `booster.feature_names`.
4. Even if `x_input` is passed as a raw NumPy array, `transform()` stacks `blocks = [num_scaled, bool_imputed]`, placing the 12 numeric columns first and `is_sm_ips_ports` at column index 12, perfectly matching `booster.feature_names`.

## 4. Verification Conclusion

There is **zero feature misalignment** between `TrafficShieldPreprocessor` and `OptunaTuned_XGBoost`.
The apparent discrepancy reported in M14.2.1 was caused solely by assuming that `feature_names_in_` positional order matched `feature_names_out_` positional order when reading a manually reconstructed array block in a markdown report.
