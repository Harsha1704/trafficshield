# TrafficShield M15.1 — High Anomaly Rate Forensic Investigation

**Document ID:** TS-M15.1-ANOMALY-AUDIT  
**Date:** 2026-10-26  
**Status:** AUDITED & EXPLAINED  
**Auditor:** TrafficShield Security & ML Engineering Team  
**Scope:** Forensic investigation of the reported 64.5% anomaly classification rate (431 / 668 flows) during passive live Wi-Fi capture.

---

## 1. Executive Summary & Core Finding

During the 24.1-second live capture smoke test on the Realtek RTL8852BE WiFi 6 adapter, **431 out of 668 scored flows (64.5%)** were classified as anomalous at decision threshold $\tau = 0.50$, resulting in **241 deduplicated security alerts** persisted to SQLite WAL.

### Definitive Root Cause:
The observed 64.5% anomaly rate is **NOT caused by an inference defect, software bug, feature miscalculation, or corrupted flow pipeline**.

Rather, it is the direct mathematical consequence of **Feature Distribution Shift (Domain Mismatch)** between:
1. The **training domain (UNSW-NB15, 2015)**: An enterprise network testbed where normal internal hosts communicated through multiple routing hops with default Linux/internal TTLs of 31 or 62 ($sttl \le 62$), and where high TTLs ($sttl \ge 254$) were almost exclusively generated by external cyber-range attack tools (Nessus, Nmap, Metasploit).
2. The **operational evaluation domain (Modern Wi-Fi Subnet, 2026)**: An unrouted local wireless link dominated by:
   - **RFC 6762 Multicast DNS (mDNS 5353)**: Mandates IP TTL = **255** for all multicast announcements.
   - **UPnP / SSDP (Port 1900)**: Frequently transmits discovery datagrams with IP TTL = **255**.
   - **Windows Workstation Local Traffic**: Transmits unicast and broadcast IP packets with standard default initial IP TTL = **128**.

Because the frozen XGBoost detector splits heavily on $sttl > 62$ to identify anomalies, **every single mDNS announcement, SSDP packet, and Windows local flow on the Wi-Fi interface triggered an anomaly score well above 0.50**.

## 3. Mathematical Attribution: Why XGBoost Classifies These Flows as Anomalous

### A. The `sttl` Decision Split in Frozen XGBoost
Inspection of the booster tree structure (`artifacts/models/production_detector.joblib`, 3,446 tree nodes) reveals:
- Feature `sttl` is used as a decision split in **254 tree nodes**.
- Preprocessor `RobustScaler` maps raw `sttl` using:
  $$\text{normalized\_sttl} = \frac{sttl - 31.0}{1.0}$$
- Across all 254 splits on `sttl`, the split boundary in raw space is strictly:
  $$\text{Split Threshold} = 62.0 \text{ to } 64.0 \quad (\text{Mean: } 62.94)$$
- In the tree logic, when $sttl > 64$, paths overwhelmingly accumulate positive log-odds, pushing the sigmoid anomaly probability $P(\text{anomaly}) \ge 0.50$.

### B. Distribution of `sttl` in Live Wi-Fi Traffic
| Raw `sttl` Value | Number of Persisted Alerts | Percentage | Typical Origin |
|:---:|:---:|:---:|:---|
| `255` | 180 | **74.7%** | RFC 6762 mDNS, SSDP multicast |
| `128` | 40 | **16.6%** | Windows 11 host outbound TCP/UDP |
| `127` | 10 | **4.1%** | Windows 1-hop routed / gateway packets |
| `118` | 2 | **0.8%** | External CDN / Cloudflare inbound packets |
| `64` | 9 | **3.7%** | Linux / Android local device traffic |

**Result:** **96.3% of all live alert flows had $sttl > 64$**, directly triggering the high-anomaly branches of the XGBoost booster.

### C. Single-Packet Flow Characteristics
- **75.5% of alerts (182 flows)** were single-packet flows:
  - $\text{duration\_seconds} = 0.0$
  - $\text{fwd\_packets} = 1$
  - $\text{sload} = 0.0$, $\text{sjit} = 0.0$, $\text{sintpkt} = 0.0$
  - $\text{swin} = 0.0$ (UDP)
  - $\text{packet\_rate} = 0.0$, $\text{byte\_rate} = 0.0$
- In UNSW-NB15, normal web browsing traffic consists of multi-packet TCP streams with active window sizes ($\text{swin} = 255$, $\text{fwd\_packets} \ge 10$, $\text{packet\_rate} > 50$). Single isolated UDP packets with zero duration and $sttl = 255$ closely resemble reconnaissance port-scans or probing in that feature space.

## 4. Reconciliation of Flow Counts

### Question 1: Why did 757 completed flows yield only 668 scored flows?
- **Total Flows Produced by Flow Builder:** **757 flows** (including active flows flushed at shutdown via `flow_builder.flush()`).
- **Flows Processed by Inference Worker:** **668 flows**.
- **Incompatible Flows Rejected (`is_compatible = False`):** **0 flows**.
- **Validation Errors:** **0 flows**.
- **Unscored In-Flight Flows:** **89 flows** ($757 - 668 = 89$).

**Mechanism:** When the operator calls `POST /api/v1/capture/stop`, `RealTimeDetectionManager.stop()` flushes remaining active flows from `UnidirectionalFlowBuilder` into `flow_queue`, and simultaneously signals `inference_worker.stop()`. The worker loop condition `while not self._stop_event.is_set():` terminates the loop, leaving 89 flushed flows in the queue. They were not rejected; they were halted as part of graceful worker shutdown.

### Question 2: Why did 431 anomalous flows produce 241 persisted alerts?
- **Total Flows Scored Anomalous ($P \ge 0.50$):** **431 flows**.
- **Deduplication Key:** `(src_ip, dst_ip, dst_port, protocol)`. (Source port is intentionally excluded to prevent ephemeral port flooding).
- **Deduplication Sliding Window:** **10.0 seconds**.
- **Deduplicated Discarded Alerts:** **190 flows** ($431 - 241 = 190$).
- **Persisted Alerts in Database:** **241 unique records** (`source="LIVE_CAPTURE"`).

**Mechanism:** In ambient local traffic, periodic broadcast protocols (such as mDNS repeating queries every few seconds) emit multiple consecutive anomalous flows between the same host and multicast group within 10 seconds. The deduplicator successfully suppressed 190 redundant alerts, protecting the SOC analyst from alert fatigue.

## 5. Summary of Findings

1. **Feature Fidelity Verified:** All 13 model features (`duration_seconds`, `fwd_bytes`, `sttl`, `sload`, `fwd_packets`, `swin`, `smeansz`, `sjit`, `sintpkt`, `is_sm_ips_ports`, `packet_rate`, `byte_rate`, `bytes_per_packet`) strictly adhere to the frozen contract.
2. **Zero Software Defect:** The flow constructor, packet validator, preprocessor, and XGBoost booster behaved deterministically and correctly.
3. **No Retraining or Fabrication:** The model was not modified, retrained, or altered.
4. **Domain Shift Identified:** The elevated anomaly rate reflects real domain shift between 2015 synthetic enterprise testbed data and 2026 local wireless broadcast/multicast traffic.
