## 1. Threat Model & Attack Surface

TrafficShield is an industry-oriented network anomaly detection system deployed on sensitive enterprise and industrial networks. Its threat model considers four primary threat vectors:
1. **Unauthenticated Network Attackers:** External or untrusted network callers attempting to probe internal endpoints, brute-force credentials, execute denial-of-service against inference endpoints, or extract infrastructure information.
2. **Untrusted Data Feeds:** Malicious or malformed network flow telemetry containing reverse-direction leakage fields, labels, oversized payloads, non-numeric values, or out-of-range rates.
3. **Privilege Escalation:** Authenticated SOC analysts attempting to perform unauthorized administrative mutations (e.g. promoting unvetted candidate models or altering governance registry states).
4. **Supply Chain & Model Tampering:** Insertion of backdoor-modified model weights or preprocessor pickles into the deployment filesystem.

## 2. Security Controls & Defenses

### 2.1. Authentication & Session Security (OWASP API1, API2)
- **Credential Storage:** Passwords are never stored in plaintext. Passwords are salted and hashed using scrypt/PBKDF2 via `werkzeug.security.generate_password_hash`.
- **Account Enumeration Defense:** `/api/v1/auth/login` returns a generic `"Invalid username or password"` response (HTTP 401) for both non-existent usernames and incorrect passwords. In addition, when an invalid username is submitted, a constant-time dummy password hash verification executes to prevent timing analysis attacks.
- **Brute-Force Abuse Prevention:** Login attempts are rate-limited via `Flask-Limiter` (`10 per minute` per client IP).
- **Session Tokens:** Sessions use signed, time-limited cryptographic tokens generated by `itsdangerous.URLSafeTimedSerializer` with the application secret key and dedicated salt (`trafficshield-auth-v1`).
- **Cookie Security:** The `trafficshield_session` cookie enforces `HttpOnly=True` (preventing JavaScript access and XSS theft), `SameSite=Lax` (preventing CSRF), and `Secure=True` in production (enforcing HTTPS transmission).

### 2.2. Server-Side Role-Based Access Control (RBAC) (OWASP API5)
- All protected endpoints enforce server-side validation via the `@require_role` decorator:
  - **Public (Unauthenticated):** `/api/v1/health` (liveness), `/api/v1/ready` (sanitized readiness), `/api/v1/auth/login`, `/api/v1/model/info`.
  - **Analyst Role:** Can score flows (`/predict`, `/predict/batch`), inspect alerts, update investigation notes and triage statuses, view drift telemetry and baseline metrics, and submit investigation feedback.
  - **Admin Role:** Extends Analyst privileges with exclusive authorization to approve model promotions in the model registry (`/monitoring/registry/promote`) and manage system configuration.
- **Verification:** Automated tests verified that an analyst token attempting to promote a candidate model is denied with `HTTP 403 FORBIDDEN` (`test_analyst_forbidden_from_promoting_model`).

### 2.3. Model Artifact Integrity & Anti-Tampering (OWASP API8)
- Serialized machine learning models (`.joblib` / `pickle`) can execute arbitrary Python bytecode upon deserialization.
- **Control:** `ProductionInferenceService.load_artifacts()` computes the SHA-256 hash of `production_detector.joblib` and `production_preprocessor.joblib` before deserialization.
- Hashes are compared against immutable reference checksums established in Milestone 9:
  - Model: `c43bb5cabd848f930eb7a977b730e401bd8204d6dd63170d1d2f2df2e4d27495`
  - Preprocessor: `effe96e1977ce9687eb602a953f34f70a42ee1881bf678f59c40b99a1eecc653`
- If an artifact is altered by even a single bit or replaced with an untrusted file, deserialization is aborted and a `RuntimeError` fails closed. Verified via `test_tampered_model_artifact_fails_closed`.

### 2.4. Production Error Shielding & Information Disclosure (OWASP API3)
- In production, unhandled exceptions and database failures return generic error payloads:
  ```json
  {
    "status": "error",
    "error": {
      "code": "DEPENDENCY_UNAVAILABLE",
      "message": "One or more readiness checks failed"
    }
  }
  ```
- Raw Python tracebacks, database connection strings, database usernames, and local filesystem paths (`/var/db/...`) are strictly suppressed from client responses.

### 2.5. Browser Defense-in-Depth & Security Headers
Every HTTP response issued by TrafficShield attaches defensive browser headers:
- `Content-Security-Policy`: Restricts scripts and framing to self (`frame-ancestors 'none'`).
- `X-Frame-Options: DENY`: Prevents UI redressing and clickjacking.
- `X-Content-Type-Options: nosniff`: Prevents MIME-type confusion attacks.
- `Referrer-Policy: strict-origin-when-cross-origin`: Minimizes referrer leakage.
- `Permissions-Policy`: Restricts sensitive browser APIs (`geolocation=(), microphone=(), camera=()`).
- `Strict-Transport-Security`: Enforces HTTPS for 1 year (`max-age=31536000; includeSubDomains`) when in production.

### 2.6. Demo Seeding Production Lock-Down
- Demonstration data seeders (`/api/v1/alerts/seed-demo` and `/api/v1/monitoring/seed-demo`) evaluate multiple production indicators:
  - `settings.is_production == True`
  - `FLASK_ENV == "production"`
  - `APP_ENV == "production"`
  - `ENV == "production"`
  - `app.config["ENV"] == "production"`
- Any production match immediately aborts with `HTTP 403 FORBIDDEN` and error code `FORBIDDEN_IN_PRODUCTION`.
